Upgrade the existing working hypertrophy training application to V2. Preserve the current working database, user profiles, exercise library, workout history, mesocycle/workout creation functionality, and existing data unless a schema migration is required.

Do NOT rebuild the application from scratch. Modify the existing application.

The goal of V2 is to improve workout creation, live workout usability, progression logic, recovery tracking, and training records.

========================================
1. TERMINOLOGY: MESOCYCLE
========================================

Replace user-facing references to "Split" with "Mesocycle."

A mesocycle:
- Has a user-defined name.
- Contains ordered training days (Day 1, Day 2, etc.).
- Contains the exercises prescribed for each day.
- Belongs to a specific user.

When creating or editing a mesocycle, provide clear:
- Save & Exit
- Cancel

Do not leave the user uncertain whether edits were saved.

========================================
2. FIX MODAL / POPUP POSITIONING
========================================

The current Add Movement and Finish Workout dialogs can appear elsewhere on the long page depending on scroll position.

Fix this globally.

All dialogs/modals must:
- use fixed viewport positioning
- appear centered in the currently visible viewport
- remain visible regardless of page scroll position
- use an overlay/backdrop
- prevent the background page from scrolling while open
- work correctly on mobile devices

Apply this architecture to future dialogs as well.

========================================
3. EXERCISE SEARCH / CUSTOM EXERCISE
========================================

When searching the exercise library:

If the user searches for an exercise that does not exist and selects "Create custom exercise," automatically pre-populate the custom exercise Name field with the current search text.

Example:

Search:
"Chest Supported T-Bar Row"

Select:
Create custom exercise

Name should already contain:
"Chest Supported T-Bar Row"

The user should not have to type the name twice.

========================================
4. BLACK / RED / WHITE THEME
========================================

Replace the existing green/cream visual identity.

Use:
- black / near-black / dark charcoal as primary colors
- white / off-white for readable content and contrast
- red as the primary action/accent color

Keep the current clean, professional layout and typography where practical.

Do NOT turn the interface into an overly aggressive bodybuilding design. It should remain clean, modern and highly readable.

Use clear visual distinction for:
- primary actions
- secondary actions
- warnings
- successful target performance

========================================
5. USER WEIGHT UNITS
========================================

Add a user preference for:

- Pounds (lb)
- Kilograms (kg)

This preference must affect:
- workout entry
- exercise targets
- previous performance
- workout history
- workout summaries
- total weight lifted
- progression recommendations

Changing units must perform real numeric conversion.

Do NOT simply change the displayed unit label.

Store data in a consistent canonical unit internally if appropriate.

========================================
6. LIVE WORKOUT EXERCISE CONTROLS
========================================

During an active workout every exercise must support:

- Add Working Set
- Remove Working Set
- Add Warm-Up Set
- Skip Exercise
- Substitute Exercise

Warm-up sets must be distinguishable from working sets.

Skipped exercises:
- should not count as completed
- should not negatively affect progression calculations
- should remain recorded as skipped for workout history

Exercise substitution must allow:
- choosing an existing exercise
- creating a custom exercise
- using the substitution for this workout
- optionally updating the mesocycle exercise permanently

========================================
7. EXERCISE CLASSIFICATION
========================================

Ensure exercises contain enough structured metadata for progression logic.

At minimum include:

- Primary muscle group
- Exercise category/type
- Compound vs non-compound
- Equipment type

Examples of equipment:
- Barbell
- Dumbbell
- Cable
- Machine
- Bodyweight
- Other

Do not destroy existing exercise records when adding these fields.

========================================
8. REP RANGES AND TARGET RIR
========================================

Exercises in a mesocycle need:

- minimum target reps
- maximum target reps
- target RIR
- minimum working sets
- maximum working sets where applicable

Example:

Bench Press
Rep range: 6-8
Target RIR: 2
Working sets: 2-4

These are performance boundaries rather than one rigid repetition prescription.

========================================
9. ADAPTIVE REP / LOAD TARGETING
========================================

This is an important V2 feature.

Weight and reps must NOT behave as two unrelated fixed recommendations.

Use previous performance, prescribed rep range and target RIR to create an adaptive performance target.

Example:

Previous:
225 lb x 6 @ 2 RIR

Next recommendation might be:
225 lb x 7 @ 2 RIR

Rep range:
6-8

If the user manually changes today's weight to 230 lb, dynamically adjust the suggested repetitions rather than treating the user as failing to follow the recommendation.

Example:

Original:
225 x 7

User chooses:
230 lb

The application may adjust the target to approximately:
230 x 6

while keeping the athlete within the prescribed performance window.

Likewise, if the athlete chooses a lower weight, the suggested reps may increase while remaining within the prescribed rep range.

The user must always remain free to enter any weight.

If the selected weight is likely to move expected performance outside the prescribed rep range, display a non-blocking warning/explanation.

Example:

"240 lb may put you below the 6-8 rep target."

Do NOT prevent the user from continuing.

Display the currently applicable:
- selected weight
- suggested reps
- acceptable rep range
- target RIR

The adaptive calculation should use the user's own exercise history whenever sufficient data exists rather than relying exclusively on generic strength percentages.

Build this calculation as a separate progression/service layer so it can be improved later without rewriting the workout UI.

========================================
10. PROGRESSION PREFERENCES
========================================

Progression should not use one universal strategy.

For compound movements:
Prefer small load progression when performance supports it, while adjusting reps downward within the prescribed rep range when appropriate.

For dumbbell, isolation and many non-compound movements:
Prefer progressing repetitions through the prescribed rep range before increasing load.

These are preferences, not rigid rules.

The adaptive rep/load system should allow either reps or load to change while keeping performance within the prescribed target window.

========================================
11. PER-SET TARGET STATUS
========================================

Every completed WORKING SET must receive a performance status.

Statuses:

TARGET MET
ABOVE TARGET
BELOW TARGET

Display an easily recognizable icon on every working-set row.

Conceptually:
✓ Target Met
↑ Above Target
↓ Below Target

Do not rate warm-up sets.

The status must NOT be based only on repetitions.

Evaluate:
- actual weight
- actual reps
- actual RIR
- dynamically calculated target
- prescribed rep range
- target RIR

Example:

Target:
225 x 7
Rep range: 6-8
Target RIR: 2

225 x 7 @ 2 RIR:
TARGET MET

If the athlete changes weight to 230 and the adaptive target becomes approximately 230 x 6 @ 2:
230 x 6 @ 2 should still be TARGET MET.

If performance clearly exceeds the adaptive target:
ABOVE TARGET

If performance clearly falls below it:
BELOW TARGET

When the user taps/clicks the status icon, show a short explanation.

Example:

Below Target

Target:
6-8 reps around 2 RIR

Completed:
5 reps @ 1 RIR

The user should understand WHY the set received its status.

Store the status and relevant target data with the completed set so historical calculations remain reproducible.

========================================
12. PROGRESSION DECISION ENGINE
========================================

Create a modular progression engine.

Do NOT reduce progression to a single simplistic rule.

Internally consider:

- recent performance
- reps
- load
- actual RIR vs target RIR
- per-set target statuses
- exercise type
- rep range
- recent performance trend
- recovery
- current weekly muscle volume

Possible recommendation outcomes include:

- INCREASE LOAD
- INCREASE REPS
- INCREASE SETS
- DECREASE SETS
- MAINTAIN

Do not force progression every workout.

MAINTAIN is a valid successful recommendation.

A single unusual workout should not automatically cause major program changes.

========================================
13. SET / VOLUME PROGRESSION
========================================

Sets must become a real progression variable.

Do NOT automatically add sets because an athlete had one successful workout.

Evaluate approximately 2-3 recent exposures to the muscle/exercise before changing training volume where possible.

If current volume is producing continued progress:
MAINTAIN SETS.

If performance has stalled across repeated exposures, effort is appropriate, recovery is good, and current weekly volume is reasonable:
consider +1 working set.

When increasing volume:
generally add only ONE working set to ONE appropriate exercise for that muscle rather than adding sets to every exercise.

If recovery is poor and performance is repeatedly declining:
consider -1 working set.

Respect configured minimum and maximum working-set boundaries.

Track total weekly working sets per primary muscle.

========================================
14. RECOVERY TRACKING
========================================

Add lightweight recovery tracking.

At the beginning of a workout ask one quick readiness question:

"How ready do you feel to train today?"

Suggested responses:
- Great
- Normal
- Below Normal
- Poor

Do not make this a lengthy questionnaire.

Also support muscle-specific recovery information when a muscle is trained again.

Example:

"How recovered does your chest feel from its last session?"

Suggested responses:
- Fully recovered
- Slightly fatigued
- Still sore/fatigued
- Very sore or limiting

Recovery decisions should combine subjective feedback with objective performance history.

Do not allow one recovery answer to automatically rewrite the program.

Use trends.

Examples:

Recovered + progressing:
Maintain volume.

Recovered + repeatedly stalled:
Potential candidate for additional volume.

Poor recovery + repeated performance decline:
Potential candidate for reduced volume.

Poor subjective recovery but improving performance:
Do not automatically reduce volume; continue monitoring.

========================================
15. PAIN / JOINT DISCOMFORT
========================================

Keep pain/joint/tendon discomfort separate from normal muscle recovery.

Do not attempt medical diagnosis.

If meaningful discomfort is reported:
- avoid automatically recommending additional load or volume for that movement
- allow easy exercise substitution
- record the feedback for trend/history purposes

Do not treat joint discomfort as simply another recovery score.

========================================
16. TRAINING RECORD / TOTAL WEIGHT LIFTED
========================================

The application currently displays "Volume" as weight x reps.

Keep the calculation internally, but change the primary user-facing terminology to:

TOTAL WEIGHT LIFTED

Example:

TOTAL WEIGHT LIFTED
12,900 lb

Calculate this from WORKING SETS.

Do not include warm-up sets in this headline statistic.

Also provide a breakdown by PRIMARY MUSCLE GROUP.

Example:

Chest       7,830 lb
Shoulders   2,140 lb
Triceps     2,930 lb

TOTAL      12,900 lb

The muscle-group totals MUST add up exactly to the workout total.

Do NOT double-count compound movements across multiple muscles.

For this statistic, attribute each exercise's weight moved to its PRIMARY muscle group only.

Do not use total weight lifted as a direct measure of hypertrophy effectiveness or as the primary progression variable.

========================================
17. FINISH WORKOUT
========================================

Fix the Finish Workout dialog positioning as described earlier.

When finishing:

- validate/save completed sets
- save skipped exercises
- save readiness/recovery information
- calculate per-set target statuses
- calculate total weight lifted
- calculate primary-muscle totals
- store the completed workout
- show a workout summary
- close the active session
- advance the athlete to the next training day in the mesocycle

The completed workout must not remain as an active session after finishing.

========================================
18. MESOCYCLE-AWARE ARCHITECTURE
========================================

Prepare the data model for future mesocycle-level progression.

We do NOT need a sophisticated deload algorithm in this V2 build.

However, track enough information to later support:

- mesocycle start date
- current mesocycle week
- exercise progression over the mesocycle
- working sets by muscle/week
- recovery trends
- accumulated performance trends
- future deload/end-of-mesocycle recommendations

Do not automatically implement aggressive deload behavior yet.
