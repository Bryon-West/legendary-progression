We have real beta testers actively using Legendary Progression.

This task adds:

1. User-selectable BASIC and LEGENDARY PRO training modes
2. Safe mode switching between workouts
3. A simplified Basic workout experience
4. Exercise hamburger action menus
5. Clear Add Set / Remove Set controls
6. User-facing PWA installation
7. Automatic PWA update handling
8. App/build version display

IMPORTANT:

- Preserve all existing user/tester data.
- Preserve the existing Legendary Pro progression engine.
- Do not change progression mathematics unless required to fix a regression caused by this task.

- NO automatic publishing.
- Do not add payments, subscriptions, Stripe, or advertisements yet.

1. BASIC AND LEGENDARY PRO TRAINING MODES
==================================================

Add two account training modes:

BASIC
LEGENDARY PRO

==================================================
5. BASIC MODE
==================================================

Basic should be a clean, simple manual workout tracker.

The normal Basic workout flow should essentially be:

Choose exercise
→ enter weight
→ enter reps
→ log set
→ continue
→ finish workout

Basic keeps:

- exercises
- routines/splits
- calendar/workout scheduling
- warm-up sets
- working sets
- weight
- reps
- Add Set
- Remove Set
- completed workouts
- workout history
- PR tracking
- Total Weight Lifted
- basic workout summaries
- exercise library
- lb/kg
- manual workout structure changes
- existing applicable calendar/history functionality

Basic should NOT contain RIR.

Do not display or require:

- target RIR
- actual RIR
- RIR inputs
- RIR prescriptions
- RIR-based evaluation

Basic workout sets must be valid with weight/reps and no RIR.

Store missing RIR as null/unknown where appropriate.

NEVER fabricate RIR for Basic workouts.

==================================================
6. BASIC HAS NO PROGRESSION ENGINE
==================================================

Basic does NOT automatically decide what the user should do next.

Do not display/use:

- automatic weight recommendations
- automatic rep recommendations
- automatic set progression
- set-specific progression targets
- Above Target
- Target Met
- Below Target
- 5 lb ≈ 1 rep progression evaluation
- progression recommendations
- recovery-driven progression changes
- mesocycle progression intelligence
- automatic deload progression decisions
- other features whose purpose is to tell the athlete how to progress

Basic users manually choose their workout weights, reps and structure.

Do not delete the existing progression engine.

Basic simply does not use it.

==================================================
7. BASIC SKIPS PROGRESSION / RECOVERY QUESTIONS
==================================================

Basic should NOT receive the questions used by Legendary's progression/recovery system.

Skip questions including:

- muscle stimulus/pump
- target muscle fatigue
- joint/tendon discomfort
- recovery/readiness
- any other question whose purpose is feeding the progression/recovery engine

Do NOT show disabled or empty versions of these questions.

They should simply not exist in the Basic workout flow.

Basic should feel fast:

LOG → FINISH → DONE.

After completion, Basic can still display useful NON-progression information such as:

- workout completed
- exercises performed
- working sets
- Total Weight Lifted
- PRs
- workout history/basic summary

==================================================
10. CRITICAL MODE-SWITCHING RULE
==================================================

A workout must START AND FINISH in the SAME training mode.

Never allow a workout to become half-Basic and half-Pro.

Training-mode changes occur BETWEEN workout sessions.

When a workout session starts, snapshot/persist the training mode on that workout session.

Example:

session.trainingMode = BASIC

or

session.trainingMode = PRO

Once the workout starts, that session mode must remain immutable for the life of that workout.

Do not rely only on the user's current account setting because the account setting could change on another device or after a reload.

==================================================
11. SWITCHING WITH NO ACTIVE WORKOUT
==================================================

If there is NO active/in-progress workout:

BASIC ↔ LEGENDARY PRO may switch immediately.

Persist the new mode server-side.

==================================================
12. SWITCHING DURING AN ACTIVE WORKOUT
==================================================

If a workout is currently active and the user requests a mode change, DO NOT change modes immediately.

Show a confirmation dialog/bottom sheet with three choices:

FINISH CURRENT WORKOUT

Explain:
Complete today's workout using the current mode. The requested mode change will take effect after the workout is successfully finished.

CANCEL TODAY'S WORKOUT

Explain:
Cancel/discard today's unfinished workout, then change Training Mode.

KEEP CURRENT MODE

Explain:
Continue today's workout without changing modes.

Do NOT provide:

"Switch Anyway"

or any mechanism that creates a mixed Basic/Pro workout.

==================================================
13. FINISH CURRENT WORKOUT THEN SWITCH
==================================================

PRO → BASIC:

The active Pro workout must finish completely as Pro.

All normal Pro:

- questions
- calculations
- persistence
- progression evaluation

must finish normally.

Only AFTER successful workout completion should Basic become the account's active mode.

The NEXT workout is Basic.

Do not strip Pro data from the completed workout.

BASIC → PRO:

The active Basic workout must finish completely as Basic.

Do not retroactively add:

- RIR
- recovery answers
- targets
- progression evaluation

Only AFTER successful completion should Pro become active.

The NEXT workout is Pro.

If workout completion/save fails:

DO NOT change modes.

==================================================
14. CANCEL TODAY'S WORKOUT THEN SWITCH
==================================================

If the user chooses:

CANCEL TODAY'S WORKOUT

use Legendary's existing safe cancel/discard behavior for the CURRENT unfinished workout.

Do NOT delete:

- previously completed workouts
- history
- PRs
- previous progression data

Only cancel/discard the active unfinished session according to existing behavior.

After cancellation succeeds:

change Training Mode.

If cancellation fails:

do NOT change Training Mode.

==================================================
15. BASIC ↔ PRO DATA PRESERVATION
==================================================

Basic and Pro should use compatible underlying workout/history data.

Do not create two incompatible workout databases.

Keep the underlying schema capable of storing Pro information.

Basic simply leaves Pro-specific values null/unknown where appropriate.

BASIC → PRO:

Preserve all Basic history.

Do NOT fabricate historical RIR.

If Pro requires progression information that does not exist because workouts were performed in Basic, use Legendary's existing baseline/calibration behavior.

PRO → BASIC:

DO NOT DELETE historical:

- RIR
- progression data
- recovery answers
- targets
- PRs
- mesocycles
- completed workouts
- history

Basic simply stops displaying/using Pro progression functionality.

PRO → BASIC → PRO:

Previous legitimate Pro history must still exist when Pro is enabled again.
