2. MESOCYCLE WEEK / RIR SYSTEM
==================================================

Mesocycles must have editable training weeks.

Default loading progression:

Week 1 = 3 RIR
Week 2 = 2 RIR
Week 3 = 1 RIR
Week 4 = 0 RIR

Then optionally:
Recovery Week = Deload OR Week Off

IMPORTANT:
Do NOT hard-code the system to exactly four loading weeks.

Each mesocycle week should store its own target RIR.

Users must be able to:

+ Add Week
- Remove future/unstarted Week
+ Add Recovery Week
- Remove Recovery Week

When adding a loading week, allow the user to select the target RIR.

Suggest an appropriate value, but do not automatically create repeated 0-RIR weeks.

Example valid mesocycle:

Week 1 — 3 RIR
Week 2 — 3 RIR
Week 3 — 2 RIR
Week 4 — 2 RIR
Week 5 — 1 RIR
Week 6 — 0 RIR
Recovery — Deload

Completed weeks become historical records and should not be deletable.

Premade mesocycles are templates, NOT locked programs.
Users may add/remove future weeks and modify their RIR schedule.

==================================================
3. WEEK 1 / EXERCISE CALIBRATION
==================================================

An exercise without valid recent personal history must enter CALIBRATION MODE.

During calibration:

DO NOT prescribe a target weight.
DO NOT prescribe target reps.
DO NOT display a target performance range.

Tell the user to:

"Choose a weight you believe you can perform at approximately 3 RIR."

The user performs the exercise and records:

- weight
- reps
- actual RIR

This creates the exercise baseline.

Calibration should normally occur at approximately 3 RIR regardless of the current mesocycle week.

Calibration working sets should NOT receive:
- Above Target
- Target Met
- Below Target

because there was no valid performance target to compare against.

==================================================
4. EXERCISE BASELINE STATES
==================================================

Every exercise should independently have one of these states:

NO BASELINE
ACTIVE BASELINE
EXPIRED BASELINE

No Baseline:
The user has never established valid history for that exact exercise.

Active Baseline:
Recent personal performance exists and can be used by the progression engine.

Expired Baseline:
Old performance remains visible in history but should not be used to generate current prescriptions.

Make the baseline expiration period an engine/config setting.

Initial default:
6 weeks

Do NOT permanently hard-code the value into progression logic.

Exercise baselines are exercise-specific.

Example:
Dumbbell Bench Press history must NOT automatically create a Barbell Bench Press baseline.

Starting a new mesocycle does NOT automatically erase active baselines.

5. FIX WEEK 2+ PROGRESSION PREFILL
==================================================

CURRENT PROBLEM:
When reaching Week 2, progression values are not automatically populating the workout fields.

FIX THIS.

Once an exercise has valid personal history, the progression engine should calculate the next recommendation.

Recommended values must actually PREFILL the working-set input fields.

Prefill:

WEIGHT
REPS
TARGET RIR

Example:

Week 1 actual:
225 lb x 6 @ 3 RIR

Week 2 target:
2 RIR

The engine uses personal history to calculate the Week 2 recommendation.

The resulting Weight and Reps should already appear in the Set 1 fields when the exercise becomes active.

The user remains free to change either value.

Do not merely display the recommendation elsewhere on the screen.

==================================================
6. VALID WEIGHT INCREMENTS
==================================================

Progression recommendations must snap to usable weight increments.

Default:

POUNDS:
2.5 lb increments

Examples:
225
227.5
230
232.5

Do NOT generate values such as:
228.37 lb
231.16 lb

KILOGRAMS:
Default 2.5 kg increments.

Architect this so exercise/equipment-specific increments can be supported later.

Example future possibilities:
- 5 lb dumbbells
- 10 lb machine stack
- 2.5 lb barbell
- custom increment

The progression engine may calculate a theoretical value internally but the displayed/prescribed weight must snap to a valid load.

==================================================
7. ADAPTIVE WEIGHT / REP TARGETING
==================================================

Weight and reps are linked.

Example:

Recommended:
225 x 7

If the user changes the weight to:
230

the app may determine the equivalent target is approximately:
230 x 6

Likewise, selecting a lower weight may increase the expected reps.

Use the user's PERSONAL exercise history whenever possible.

Do not rely primarily on generic strength percentages.

The user is always allowed to override the recommendation.

The system should coach, not block.

==================================================
8. COMPLETE SET WORKFLOW
==================================================

Implement sequential set completion similar to the previous Excel design.

Example:

WORKING SET 1
Weight: [225]
Reps: [7]
RIR: [2]

[ COMPLETE SET ]

Set 2 remains locked until Set 1 is completed.

When Complete Set is pressed:

1. Validate required fields.
2. Save the set.
3. Determine Target Status if applicable.
4. Lock the completed set.
5. Calculate/update the next recommendation.
6. Unlock and PREFILL Set 2.

Repeat for subsequent sets.

Completed sets should be read-only unless the user deliberately presses EDIT.

Editing a completed set should trigger recalculation of any later uncompleted recommendations when necessary.

Do not allow Complete Set until required values are entered.

10. WARMUP SETS
==================================================

Warmup sets are separate from working sets.

Warmups:

- may be added
- may be completed
- may be removed
- do NOT receive Target Status
- do NOT count toward hypertrophy progression
- do NOT count toward Total Weight Lifted

Keep warmup data available within the workout record where appropriate.

==================================================
11. TARGET STATUS
==================================================

For working sets with a VALID performance target, assign:

↑ ABOVE TARGET
✓ TARGET MET
↓ BELOW TARGET

Determine this using:

- recommended weight
- actual weight
- recommended reps
- actual reps
- prescribed RIR
- actual RIR
- personal exercise history

Do NOT judge status from reps alone.

Allow the status icon/label to be tapped to explain why the set received that status.

Warmups receive no status.

Calibration sets receive no performance status because no valid target existed.

==================================================
12. PROGRESSION DECISION ENGINE
==================================================

Keep/refactor progression logic into a modular service layer.

Possible progression outcomes:

INCREASE LOAD
INCREASE REPS
INCREASE SETS
DECREASE SETS
MAINTAIN

MAINTAIN is a successful and legitimate result.

Progression decisions should consider:

- recent exercise performance
- actual vs prescribed RIR
- load
- reps
- recent exposure trend
- muscle recovery
- readiness
- current weekly muscle volume
- current working-set count
- exercise type/equipment

Avoid changing program volume based on one isolated workout.

==================================================
13. SET / VOLUME PROGRESSION
==================================================

The application must be capable of intelligently changing working-set counts.

Look at approximately 2–3 recent exposures.

General logic:

Progressing + recovered:
MAINTAIN sets.

Repeated stall + good recovery + appropriate effort:
Candidate for +1 working set.

Repeated performance decline + poor recovery:
Candidate for -1 working set.

Only change one appropriate exercise when increasing muscle volume.

Do NOT automatically add a set to every exercise targeting the same muscle.

Respect configured min/max working-set limits.

==================================================
14. RECOVERY / READINESS
==================================================

Keep the recovery system lightweight.

At the beginning of a workout:

How do you feel today?

- Great
- Normal
- Below Normal
- Poor

When relevant, collect muscle recovery:

- Fully recovered
- Slightly fatigued
- Still sore/fatigued
- Very sore or limiting

Combine subjective recovery with objective performance.

One poor readiness answer must not automatically rewrite the entire program.

==================================================
15. PAIN / DISCOMFORT
==================================================

Keep joint/tendon pain or discomfort separate from normal muscular fatigue.

When pain/discomfort is reported:

- avoid automatic aggressive progression
- make exercise substitution easy
- preserve workout history
- do not diagnose the user

==================================================
16. RECOVERY WEEK
==================================================

Allow an optional Recovery Week at the end of a mesocycle.

Choices:

DELOAD
WEEK OFF

Deload:
Reduce training workload and effort using configurable deload settings.

Use higher RIR and reduced working volume.

Do NOT treat reduced deload performance as normal performance decline.

Week Off:
No scheduled lifting.

Week Off should NOT:

- count as missed workouts
- hurt progression
- create negative recovery scoring
- immediately expire otherwise valid exercise baselines

Clearly label:

RECOVERY WEEK — DELOAD

or

RECOVERY WEEK — WEEK OFF

18. MOVE / RESCHEDULE WORKOUTS
==================================================

Allow future/uncompleted workouts to move earlier or later within the same mesocycle week.

Example:

Wednesday workout missed.

Move it to Thursday.

Preserve:

- mesocycle week
- target RIR
- exercises
- programming
- progression state

If the move creates closely spaced sessions, show a recovery warning but DO NOT block the move.

Optionally offer:

Completed workouts cannot simply be moved/re-written.

Until the week closes, an unperformed workout should remain:

NOT COMPLETED / RESCHEDULE

rather than immediately being treated as a progression failure.

==================================================

TOTAL WEIGHT LIFTED

not "Volume" where the user sees the workout summary.

working-set weight x completed reps

Exclude warmups.

Total Weight Lifted

Do NOT use Total Weight Lifted by itself as the hypertrophy progression metric.
